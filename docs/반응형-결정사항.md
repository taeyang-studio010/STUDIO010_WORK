# 반응형 웹 적용 – 결정 사항 (권한 요청)

휴대폰·태블릿에서도 디자인 이쁘고 모든 기능이 잘 동작하도록 반응형 적용하기 전에, 아래 결정 사항에 대해 **승인** 부탁드립니다.  
승인해 주시면 이 기준으로 전체 구현하겠습니다.

---

## 1. 브레이크포인트

| 구간 | Tailwind | 용도 |
|------|----------|------|
| 모바일 | 기본 (~639px) | 1열 레이아웃, 햄버거 메뉴 |
| 태블릿 | `sm:` 640px, `md:` 768px | 2열 그리드, 여백 조정 |
| 데스크톱 | `lg:` 1024px (현행 유지) | 사이드바 펼침, 3열 등 |

- **결정:** 위 3단계 유지. 현재 `max-lg` 쓰는 곳은 그대로 두고, 모바일/태블릿용으로 `sm`/`md` 추가.
- **승인 여부:** ✅ 승인 (2026-02-21)

---

## 2. 모바일 네비게이션 (사이드바)

- **현재:** 1024px 미만에서 사이드바가 72px 좁은 버전(아이콘만). 72px도 작은 화면에서는 공간을 많이 씀.
- **제안:** 768px 미만(md 미만)에서는 사이드바를 **완전히 숨기고**, 대신 **상단 헤더 + 햄버거 버튼** → 탭 시 **왼쪽에서 슬라이드인 드로어(메뉴)** 로 열기. 드로어 밖 탭/스와이프 시 닫기.
- **결정:** 모바일 = 햄버거 + 슬라이드 드로어. 태블릿(768~1023px)은 기존처럼 72px 좁은 사이드바 유지.
- **승인 여부:** ✅ 승인 (2026-02-21)

---

## 3. 메인 콘텐츠 여백

- **현재:** `pl-[240px] max-lg:pl-[72px]` (사이드바만큼 왼쪽 여백).
- **제안:** 모바일(드로어 사용 시)에는 `pl-0`, 상단 헤더 높이만큼 `pt-14` 정도 적용해 콘텐츠가 전체 너비 쓰도록.
- **결정:** 모바일 = 왼쪽 패딩 제거 + 상단 고정 헤더 높이만 반영.
- **승인 여부:** ✅ 승인 (2026-02-21)

---

## 4. 그리드·카드 레이아웃

- **010 NOW 메인:** KPI 3열 → 모바일 1열, 태블릿 2열. 하단 2x2 → 모바일 1열.
- **기타 페이지:** tasks(칸반), calendar, budget, insights, talk 등도 동일 원칙 – 작은 화면에서 1열, 중간에서 2열.
- **결정:** 작은 화면은 1열 우선, `sm:`/`md:`/`lg:` 로 단계적 2열·3열.
- **승인 여부:** ✅ 승인 (2026-02-21)

---

## 5. 모달 (추가·편집 등)

- **현재:** 중앙 소형 모달(max-w-md), p-4.
- **제안:** 768px 미만에서는 **전체 화면 또는 하단 90% 시트** 형태로 표시. 닫기 버튼은 상단 오른쪽 유지. 스크롤 가능하게.
- **결정:** 모바일 = 풀스크린 또는 하단 시트형 모달. 기존 모달 컴포넌트에 `max-md:` 로 분기.
- **승인 여부:** ✅ 승인 (2026-02-21)

---

## 6. 010 TALK (채팅)

- **현재:** 채팅 목록 + 메시지 영역. 작은 화면에서 비율 조정 필요.
- **제안:** 모바일에서 입력창·메시지 목록 터치 영역 넉넉히, 가상 키보드 올라와도 입력창이 가리지 않도록 하단 고정 + safe-area 반영.
- **결정:** 모바일에서 입력창 하단 고정, safe-area, 터치 영역 44px 이상.
- **승인 여부:** ✅ 승인 (2026-02-21)

---

## 7. Activity Feed (메인 페이지 오른쪽 패널)

- **현재:** 데스크톱에서 메인 옆 고정 패널.
- **제안:** 1024px 미만에서는 **접을 수 있는 패널** 또는 **하단 시트/탭**으로 열기. 기본은 접힌 상태로 두어 메인 콘텐츠가 넓게 보이게.
- **결정:** lg 미만에서 Activity Feed는 접기/펼치기 토글. 펼치면 위에서 내려오거나 하단 시트 형태.
- **승인 여부:** ✅ 승인 (2026-02-21)

---

## 8. 터치·접근성

- **제안:** 버튼·링크 최소 터치 영역 **44x44px** (Apple HIG). 작은 버튼은 패딩으로 보완.
- **결정:** 전역적으로 버튼/네비 링크 최소 높이 44px 또는 padding 확보.
- **승인 여부:** ✅ 승인 (2026-02-21)

---

## 9. 로그인·회원가입 페이지

- **현재:** 이미 단일 컬럼 형태.
- **제안:** 모바일에서 입력 필드·버튼 크기만 넉넉히, safe-area만 추가.
- **결정:** 반응형 유지 + 터치 영역·safe-area만 보강.
- **승인 여부:** ✅ 승인 (2026-02-21)

---

## 10. 캘린더·칸반·예산 테이블

- **캘린더:** 모바일에서 주간/일간 뷰 위주, 터치 스와이프로 주 이동 가능하면 좋음 (선택).
- **칸반:** 컬럼이 많으면 가로 스크롤 허용, 카드 터치 영역 넉넉히.
- **예산:** 테이블은 가로 스크롤 또는 카드형 리스트로 전환.
- **결정:** 작은 화면에서 가로 스크롤 또는 카드형 전환으로 기능 유지. 스와이프는 1차 구현 후 필요 시 추가.
- **승인 여부:** ✅ 승인 (2026-02-21)
